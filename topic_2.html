Topic 2: Understanding the Structure of URLs

The 6 Crucial Pieces of a URL

Upon creation of the URL, Sir Berners-Lee comprised this component of six crucial parts.

  • The Scheme
  • The Host
  • The Port
  • The Path
  • The Query
  • The Fragment

The Scheme

The scheme serves as the first piece of a URL. The point of the scheme is to communicate with web servers, allowing them to know which protocol to use i.e., https: in the case of this example.

This piece of the URL isn't commonly represented anymore because of how ubquitous it has become in the structure of URLs. If you look at web addresses now, you may not see the scheme however, this isn't the case for schemes that are rare compared to https. Of the likes of ftp and mailto, any uncommon schemes are explicitly written within the URL, but for everyday internet usage, this is far from common.

The Host and Port

After the scheme, colon and double slashes, we can find the host and the port. The host or domain name is the most common and recognizable piece to the URL. In the case of the example, www.welcometothejungle.com, is the host/domain name.

The host is important as it serves to fetch the respective Internet Protocol address that is hosting the webpage you're trying to reach. This is done by matching the domain name to their respective IP addresses. Once matching, comes the importance of the port portion of the URL

The port number acts as an extension of both the scheme and the host. Port numbers tend to follow a standard with the likes of 443 being the standard number for the https scheme. Once the host and port are established, a connection is established to the specific pages hosted by a server. Once this connection is established, comes the path component.

The Path

The path as its name suggests is a portion of URL that directs users to a certain path within a web address. The path will either default to the home page of a web address or path its way to the specific page you are trying to reach.

Looking at the example above, we can see an example of this. After the port (:443), comes a slash which begins the path process. Starting with just the home page through en, another slash is placed directing the user to the job section of the web page. Paths can be seen as a sequence with each slash narrowing the search down.

The Query

Once the path is established, comes an optional piece for web pages. However, queries are a crucial piece for dynamic web pages. The query serves as a means to act as a filter when it comes to searching for something. For example, if you type a question into Google search, that is a query, as the URL is filtering databases based off what was asked of it.

If you look at the structure of a query, it begins with a question mark. Afterwards, it's followed with keywords that filter what is being asked of it. This serves a crucial piece to give users exactly what they're looking for or anything closely related to it.

The Fragment

The fragment is the final and yet another optional piece to URL structure. Despite being optional, the fragment still exists to serve a purpose. Starting with a hash tag, the fragment acts as a pointer to a specific resource in a web address. For example, the likes of a specific heading in an article or a specific timestamp in a video.


Conclusion

Without URL structure, the internet would feel more of a hinderance than a tool. With the exceptional mind of Sir Berners-Lee and the creation of the URL, the navigation of the web is a seemless process, allowing us to receive just what we need.
